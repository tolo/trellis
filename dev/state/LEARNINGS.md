# Implementation Notes

Traps, gotchas, and non-obvious patterns from implementing Trellis. Bar for inclusion: *"Would a competent developer with access to the code and git history still get bitten by this?"*

---

## Expression Evaluator

- **`|` token is overloaded**: Pipe operator (filter chains) and literal substitution delimiter share the same character. Parser disambiguates by position — `|` in `_parsePrimary()` = literal sub opener, `|` after expression in `_parsePipe()` = pipe filter.
- **`!` must be scanned after `!=`**: Longest-match-first in the scanner — `!=` checked before `!`, or `!==` expressions break.
- **`scanRawUntil()` for non-expression content**: URL paths (`@{/path}`) and message keys (`#{greeting.formal}`) contain characters (`.`, `/`, `-`) that would normally be tokenized. Use raw text scanning to read them as-is.
- **Filter args are primary-level only**: `_parseFilterArg()` accepts literals, booleans, null, and bare identifiers — NOT full expressions or operators. Keeps parsing unambiguous with the `:` delimiter.
- **Cross-file fragment regex needs greedy match**: Group 2 in `~{file :: card(${x}, ${y})}` must use `(.+)` (greedy) — lazy `(.+?)` breaks on `}` inside `${...}` expressions.
- **URL expression encoding uses `Uri.encodeComponent` (RFC 3986)**: `@{}` URL expression parameter values are percent-encoded with `Uri.encodeComponent()` — spaces become `%20`, not `+`. The previous `Uri.encodeQueryComponent()` followed HTML form encoding (`application/x-www-form-urlencoded`). The `package:html` serializer then HTML-entity-escapes attribute values (`&` → `&amp;`) — this double layer is correct and expected in rendered output.

## DOM Processing

- **Children snapshot before iteration**: Always iterate `List<Element>.from(element.children)` — DOM mutations during processing (inserts, removes) corrupt the live child list.
- **`package:html` Text node auto-escapes on serialization**: For `tl:text`, setting `Text.data` is sufficient — the HTML serializer escapes `<>&"`. But inside `<script>`/`<style>`, content is raw text with no auto-escaping — `tl:inline` JS/CSS modes must manually escape.
- **`tl:block` self-closing tags consume siblings**: HTML5 parser ignores `/>` on unknown elements like `<tl:block/>`, swallowing everything after it as children. Fixed with pre-parse normalization (`<tl:block .../>` → `<tl:block ...></tl:block>`), but the normalizer must be quote-aware — `>` inside attribute values like `tl:if="${count > 0}"` must not trigger the rewrite.
- **Fragment definitions are removed from output only if parameterized**: Non-parameterized fragments remain in output for backward compatibility. Parameterized ones (`tl:fragment="name(arg)"`) are removed (step 3.5) to prevent evaluating `${param}` in the definition's outer context.
- **Fragment registry stores param names at pre-scan time**: The `tl:fragment` attribute is stripped during processing, so param names must be captured during the `collectFragments()` pre-scan, not at resolution time.
- **Cycle detection uses string IDs, not element identity**: Fragments are cloned before processing, so element identity doesn't work. IDs are `"name"` for same-file, `"file::name"` for cross-file.

## HTML5 Parser Boundary

Templates are parsed by `package:html` (a spec-compliant HTML5 parser) *before* any `tl:*` processor runs. The tokenizer/tree-builder silently mutates malformed input – and those mutations are invisible in the post-parse DOM, so the resulting bugs are silent (wrong output, no error). The validator surfaces them by reading `HtmlParser.errors` (curated allowlist in `_surfacedParseErrors`), since the runtime cannot detect them after the fact.

- **Duplicate attributes are dropped at tokenization**: `<el tl:attr="a=${x}" tl:attr="b=${y}">` keeps only the *first* `tl:attr` – the tokenizer drops the duplicate when emitting the start-tag token (parse error `duplicate-attribute`) and `element.attributes` is a map, so the processor never sees the second. A runtime "merge multiple `tl:attr`" is therefore impossible – the data is gone before trellis runs. Correct authoring: one comma-separated `tl:attr` per element. Detection is only possible via parse errors.
- **`tl:each` on `<tl:block>` inside `<table>`/`<select>` is foster-parented out**: An unknown element in "in table" insertion mode hits `startTagOther`, which emits parse error `unexpected-start-tag-implies-table-voodoo` and relocates the node out of the table – detaching the loop scope (symptom: right row/option count, empty cells). This is the HTML5 foster-parenting rule, not a trellis bug, so it can't be prevented. Correct authoring: put `tl:each` (and other `tl:*`) directly on `<tr>`/`<option>`, not a wrapping `<tl:block>`.

## Processor System

- **`ProcessorContext.domProcessor` is typed as `dynamic`**: Avoids circular import between `processor_api.dart` and `processor.dart`. Processors cast when they need DomProcessor methods.
- **Dart `_` prefix is library-private, not class-private**: Processors in separate files cannot access `_evaluator` on `ProcessorContext` — must be public despite being "internal."
- **`ProcessorPriority.afterIteration.index` can't use dot shorthand**: Dart infers context type as `num` (from `.index`), not `ProcessorPriority`. Explicit `ProcessorPriority.afterIteration.index` is required.
- **Attribute conflict: both custom and built-in fire**: When a custom processor has the same attribute as a built-in, both execute (built-in first). True replacement requires `Dialect` with `includeStandard: false`.

## Filter System

- **`Map<String, Function>` not `Map<String, dynamic Function(dynamic)>`**: The narrower type can't accept new-style `Function(dynamic, List<dynamic>)` filters. `Function` (untyped) enables runtime arity detection without ugly casts.
- **Arity detection via `NoSuchMethodError`**: `(filter as dynamic)(value, args)` — old-style (1-arg) filters throw `NoSuchMethodError`, caught and retried without args. Consistent with `_autoConvert()` pattern.

## Strict Mode

- **Null value is not undefined**: `context.containsKey()` distinguishes between a missing key and an explicit `null` value. `{'name': null}` is valid in strict mode.
- **Null-safe traversal preserved in strict mode**: `${user.name}` where `user` is explicitly `null` returns `null` without throwing — even in strict mode.

## Engine & Caching

- **Expression cache lives on `Trellis`, not `ExpressionEvaluator`**: Evaluator instances are stateless and recreated per render. Cache on the engine persists across renders.
- **`warmUp()` counts newly cached sources, not template names**: Duplicate names or identical source content don't inflate the `loaded` count.
- **`matcher` is a runtime dependency, not dev**: `package:trellis/testing.dart` exports matcher-based APIs, so `matcher` must be a regular dependency even though it's only used in tests by consumers.
- **Remote-AOT cannot use `AssetLoader` package-source lookup without deployed sources**: Embed or materialize assets instead.

## File Watching (Dev Mode)

- **Broadcast `StreamController` for `changes` stream**: Allows multiple listeners without coupling.
- **No debounce needed**: OS-level event coalescing (inotify/FSEvents) is sufficient for dev workloads. `clearCache()` is O(1) — but that covers only the engine's consumer: `trellis_dev`'s `devMiddleware` re-validates O(tree) per event (full `listTemplates()` + `loadSync` of every template), so a burst (branch switch, `cp -r`) does repeated full scans. If that ever hurts, coalesce in the middleware, not the loader.
- **Linux needs one watch per directory** (TD-013): dart:io's `recursive: true` is a no-op there, so `FileSystemLoader` walks the tree and watches each directory. Two non-obvious parts. (1) A directory can arrive **already populated** — `mkdir -p a/b` plus a write, a checkout, a `mv` of a whole folder — and the create event for it reaches the handler only after those files exist, so installing the watch is not enough: the new subtree must also be *scanned* once and reported as a change, or the templates it brought are never seen. (2) `FileSystemDeleteEvent.isDirectory` is `false` for deletes (the entity is gone before it can be stat'd), so watches must be dropped by path prefix, not by branching on `isDirectory`.
- **Cancelling a watch is asynchronous, so `close()` must drop its controller *first***: while `close()` awaits each `cancel()`, a not-yet-cancelled watch can still deliver an event — and on Linux a *directory-create* event installs a **new** watch, which the subscription list `close()` snapshotted no longer covers (a leak `close()` cannot see), while a plain event adds to the closing controller ("Bad state: Cannot add new events after calling close"). Null the controller before cancelling: the same field then doubles as the "stop installing watches" flag.
- **`listSync(recursive: true)` aborts the *whole* walk on the first unreadable directory** (`PathAccessException`, errno 13) — one `chmod 000` subfolder anywhere under the template root would otherwise take out the entire watch setup, and the exception escapes the `FileSystemLoader` constructor. Walk directory by directory with an explicit stack and catch `FileSystemException` per directory. Same trap applies to any recursive `listSync` over user-controlled trees — and two instances remain open: `listTemplates()` and `bin/validate.dart` (TD-016).
- **A move event carries the *source* in `path`; the template name of an atomic save is on `destination`**: `sed -i`, rsync, and editor safe-writes rename `page.html.tmp` over `page.html`, which Linux/Windows deliver as one `FileSystemMoveEvent` (source `.tmp`, destination `.html`) — an extension filter on `event.path` alone silently misses it. macOS never produces move events (FSEvents reports delete + create), so the miss is invisible there. Filter on `path` OR `destination`. Two residues, recorded not fixed: (1) the SDK reuses one inotify watch descriptor per *inode* across subscriptions, so the loader's unwatch-then-rewatch on an in-place directory rename gets a fresh path binding only while it is the sole watcher of that directory — a co-resident watcher (second loader, `package:watcher`) keeps the wd alive and events keep reporting pre-rename paths; (2) on macOS/Windows an in-tree directory *rename* emits nothing until the next file-level event (native watchers report renames at directory granularity and the per-directory sync only runs on Linux), so old names keep serving from the engine cache until then — pre-existing, and Linux is now stricter.
- **A live `Directory.watch` subscription keeps the Dart VM alive** — which is the only way to observe a leaked watch from outside, since `close()` also drops the controller, so a leaked watch has nothing to emit into and stays invisible in-process. Test it out of process: a fixture that opens watches, closes the loader, and returns from `main` either exits (all cancelled) or hangs (leaked). Cheaper than a `@visibleForTesting` counter, and it tests the resource rather than the bookkeeping.
- **A watcher test can only prove the fix on the platform that was broken**: with `recursive` honoured natively on macOS, the whole Linux code path is dead there. The regression guard is a mutation run — force the native path on Linux (`_hasNativeRecursiveWatch = true`) and confirm the nested tests time out.

## Object Context

- **`toMap()` first, `toJson()` fallback**: Matches common Dart model patterns. `NoSuchMethodError` = method missing (try next); other errors = domain failure (wrap in `TemplateException`).
- **Dynamic dispatch `(target as dynamic).toMap()`**: AOT-safe — no `dart:mirrors`. This is intentional.
- **Selection merges into context**: `{...context, ...selectionMap}` — selection properties overlay but don't replace outer context variables.

## Template Inheritance

- **`tl:define` stripping must happen AFTER all merging**: The recursive `_resolveChain` must not strip `tl:define` attributes from the base template — the caller needs them to locate blocks for merging. Stripping happens once at the top level in `resolve()` after the full chain is resolved.
- **Block collection does not recurse into `tl:define` elements**: A `tl:define` inside another `tl:define` is part of the outer block's content. Overriding the outer block replaces everything, including the nested define.
- **Parent element preserved, only children replaced**: `_mergeBlocks` replaces the parent `tl:define` element's children (nodes), not the element itself. This preserves the parent element's tag, id, class, and other attributes — the child's `tl:define` wrapper element is discarded.
- **`_parse()` automatically caches and clones parent DOMs**: Parent templates loaded via `loader.loadSync()` go through the engine's `_parse()` which handles caching. Each call returns a clone, so the cached parent is never mutated by the merge operation.

## Testing

- **`FileSystemLoader` validates directory existence at construction**: Tests using `Trellis()` no-arg constructor need a `MapLoader({})` instead, or the test directory must exist.
- **`IOOverrides` CAN capture stderr**: `IOOverrides.runZoned(stderr: ...)` with a small `noSuchMethod`-based `Stdout` fake (`_BufferStdout`) captures writes reliably, even across async gaps.
- **A test server on a hard-coded port is shared state across *processes***: the E2E suites pinned 19080/19081/19082, so two concurrent `dart test` runs (two terminals, or CI alongside a local run) drove **one** server. The tell is an incrementing-counter assertion seeing `2` where it expects `1` — which reads like a logic bug, not contention. `dart_frog_e2e_test` also `lsof`+`kill`ed its fixed port, reaping the other run's server mid-request. Allocate per run (`test/_e2e_server.dart` `bootServer`), and only ever kill by a port this run allocated.
- **Binding port 0 to "find a free port" is TOCTOU, not a reservation**: `ServerSocket.bind(…, 0)` then closing returns a port nothing holds — anything can claim it before the server binds. Retry the whole boot on a fresh port rather than trusting the first pick.
- **Never `listen((_) {})` a test server's stdout/stderr**: discarding it leaves a failed boot reporting only "did not become ready", with the actual cause (port in use, compile error, missing dependency) thrown away. Buffer it and put it in the failure message.
- **Reproduce a flake before claiming it fixed**: the port collision was invisible across 12 consecutive isolated runs and 100% reproducible with two concurrent ones. A rare flake usually means the trigger is environmental (parallelism, shared ports/paths/CWD) — find the condition that makes it deterministic, then reuse that as the regression check.
- **Never bind a test server to `'localhost'` and connect by name**: `HttpServer.bind('localhost', 0)` listens on the *first* resolved address only (`::1` on macOS), but `Socket.connect('localhost', …)` reaches `127.0.0.1` before `::1` at the connect stage (the lookup itself returns `::1` first; IPv4 wins on connect). Ephemeral ports are per address family, so any unrelated process already listening on `127.0.0.1:<that port>` (VS Code helpers, VM-service ports, other test runs) silently receives the request – a wrong response, or a hang until the 30 s test timeout if it never answers HTTP. Seen as a once-in-four-runs `renderPage … HTMX` timeout in `trellis_dart_frog`; reproduced by looping bind+GET (`lsof` showed our `[::1]:P` listener beside a foreign `127.0.0.1:P` one). Bind a concrete `InternetAddress.loopbackIPv4` and build the request URI from `server.address.address` (numeric hosts skip lookup and the fallback entirely).
- **Goldens must not bake the capturing machine's timezone either.** A date-only front-matter `date: 2026-01-01` is parsed as *local* midnight; the feed `<updated>`/RSS `pubDate` then read `2025-12-31T23:00:00Z` on a CET machine and `2026-01-01T00:00:00Z` on a UTC runner. The `path_prefix` golden carried the CET form and failed on the first GitHub run. Fixture dates that end up in UTC-rendered output must carry an explicit zone (`2026-01-01T00:00:00Z`). The mtime-derived stamps have the same shape of dependence: the sitemap `<lastmod>` is the *local* calendar date of the mtime, so the pinned fixture mtime sits at **noon UTC** (a 07:25Z pin flipped the date in Anchorage). Cheap local check before pushing: `TZ=UTC dart test`, plus one far-western zone (`TZ=Pacific/Honolulu`).
- **`Directory.watch(recursive: true)` is not supported on Linux** (dart:io docs: inotify; only macOS/Windows honour `recursive`) — and it fails *silently*: no error, just no events from sub-directories. A watcher test for nested paths passes on the maintainer's Mac and times out deterministically on ubuntu CI; that is a platform gap, not a flake. Fixed under TD-013 by watching each directory individually on Linux (see § File Watching), so the test now runs on every OS. When a test *is* platform-gated, `skip: Platform.isLinux ? '<reason; TD>' : false` beats raising the timeout — but a green suite then proves nothing about the gap, so the fix must delete the skip and be verified on the platform that had it (Docker `dart:<sdk>` image, or read the ubuntu CI job).
- **`$?` after a pipeline is the *last* command's status**: `dart test … | tail; echo $?` reports `tail`'s exit code, so a failing command reads as success. Capture output first, or use `PIPESTATUS`/`set -o pipefail`. This produced a wrong conclusion about `dart test --tags=<tag>`, which exits **79** (not 0) when no test carries the tag.

## Themes & SSG (docs-site)

- **A fragment-root `tl:if` is NOT re-evaluated on cross-file insertion**: when a layout pulls a fragment via `tl:replace="~{base.html :: toc}"`, a `tl:if` on the *fragment's root element* does not gate the insertion — the fragment's raw `${...}`/`tl:` content can leak when its source var is absent. Guard at the **call site** instead: `<div tl:if="${page.toc}" tl:replace="~{base.html :: toc}"></div>`. (Arbor theme sidebar/TOC/prev-next all guard at the call site for this reason.)
- **A fragment inserted twice (responsive dual-render) must not carry a literal `id`**: a TOC/nav fragment rendered once for mobile and once for desktop (one CSS-hidden per breakpoint) puts two copies in the DOM. Any hard-coded `id`/`aria-labelledby` inside it becomes a duplicate id (invalid HTML, ambiguous ARIA). Name the region with `aria-label` on a `<nav>` instead of `aria-labelledby`+`id`.
- **Theme `theme:` values are joined then must be normalized**: theme resolution is `p.join(siteDir, 'themes', <value>)`. A relative `theme:` that escapes the site dir (`../../themes/arbor`) yields un-collapsed `..` through a non-existent `<siteDir>/themes`; `ThemeManifest.load` canonicalizes but the template `FileSystemLoader` does not, so the raw path fails. Fixed by `p.normalize`-ing `themeDir` at both computation sites in `trellis_site_builder.dart` before use.
- **`pathPrefix` belongs in emitted URLs, not the on-disk output layout**: deriving output file paths from the (prefixed) `page.url` nests pages under `output/<prefix>/` while sitemap/feeds/search/static stay at the root — un-deployable to a sub-path host. `stripPathPrefix` the url before deriving the file path so the whole `output/` tree publishes at the site root and the host mounts it under the prefix.
- **`layout: home` needs a `${page.content}` slot to be content-driven**: a home layout that renders only a hero + `${pages}` grid silently drops the `_index.md` markdown body. A landing that carries pitch/CTAs in its body needs the home layout to `tl:utext="${page.content}"` too.
- **Content-link prefixing must skip `<pre>`/`<code>`**: `package:markdown` escapes `<`, `>`, `&` inside code but leaves the attribute quote `"` **literal**, so a docs *code example* renders as `<code>&lt;link href="/css/main.css"&gt;</code>` — with real quotes. A naive `href="/…"` rewriter (for `pathPrefix`) then rewrites the URL the example is *teaching*, corrupting the docs. `applyPathPrefixToLinks` skips `<pre>`/`<code>` regions (a leading regex alternative consumed before the link pattern) so example URLs are never rewritten. Test with real markdown-rendered code (literal quotes), not `&quot;`-escaped strings.
- **Docs card summaries need `excerpt_length` or HTML leaks**: `page.summary` is the first *rendered* paragraph (with `<code>`/`<a>` tags) when no `excerpt_length` is set; a theme rendering it via `tl:text` then shows literal `<code>…</code>` tags in cards. Setting the standard `excerpt_length` param makes the engine strip tags and produce a plain-text, word-boundary-truncated summary. Blog themes (Verdant) rarely hit this because prose first-paragraphs lack inline markup; docs first-paragraphs are full of it.
- **`${site.menu}` section nodes order by `_index.md` `weight`** (then lexically): `NavigationBuilder` orders sibling *section* nodes by the section page's `weight`, mirroring the single-page rule — so a docs IA controls section order deliberately (no folder-naming tricks). With no section weights, the order is pure-lexical (backward-compatible).
- **Empty string is truthy in `tl:if`**: only null/false/0/'false'/'off'/'no' are falsy – bare guards pass '' (e.g. `href=""` self-links); use `${x != ''}` or emit null, not '' (truthiness.dart).
- **Theme bugs can hide behind the params bridge**: a theme built standalone (no site `theme_params`) uses its own unquoted `_variables.scss` `!default` values, while a bridged build substitutes generator-emitted values — so a generator bug (e.g. the 0.9.0 quoted-string params producing invalid `font-family:"..."` / `max-width:"1200px"` CSS that broke fonts and layout width on the live docs site) is invisible in standalone previews and in source-math checks (WCAG contrast computed from SCSS, tests asserting CSS *contains* values). The docs-site review verified contrast/structure mathematically but never visually rendered the bridged deployed output — the breakage shipped to production and was caught by a human. Preventive: any theme/SSG visual claim must be verified against a BRIDGED build's compiled CSS (assert no quoted CSS values) AND a rendered screenshot of the built output (agent-browser), not source math or standalone previews.

- **A theme contract test that reads manifests and compiled CSS is a wiring check, not a rendering check**: the 0.11 Folio/Meadow suites asserted params, layout names, token authority and CSS substrings, and stayed green while the hero carried 205px of dead space, the mobile disclosure panel pushed article content ~1250px down, and the dark chart-paper grid was invisible. Mutation-testing the 0.11 suite reverted three of those defects and the suite passed all three times. Assert rendered geometry (`getBoundingClientRect`) from a bridged build, not the presence of a CSS declaration — a declaration can be present, overridden, and still match `contains()`.
- **One-sided byte budgets do not protect vendored fonts**: `expect(fontBytes, lessThanOrEqualTo(240 * 1024))` guards against re-adding a full-axis file, which was never the failure mode. Truncating every `woff2` in Lattice, Folio and Meadow to **zero bytes** passed all three suites. Re-subsetting by hand produces corrupt or truncated files, not oversized ones. Assert a per-file floor and the `wOF2` magic bytes, and pin the `fvar` axis set against what the CSS requests.
- **Instantiating out a variable axis is not metric-neutral, and dropping codepoints is silent**: trimming Fraunces' `opsz` widens the headline by ~19%; a re-subset that loses `←`/`→`/`↗` renders those glyphs in the visitor's system font mid-sentence with no error anywhere. Diff the `cmap` old-vs-new after any subsetting pass, and check the result against every non-ASCII character the layouts actually emit.
- **`unicode-range` must cover everything the subset contains**: a truncated range makes the browser refuse the webfont per-glyph and fall back silently. Lattice's ranges excluded `€`, `™`, `−` and **all combining diacritics** (U+0300/0301/0303/0304/0308) that were present in the shipped files — so any NFD-normalised accent, which is what macOS and many CMS pipelines emit, rendered in the system font. Either emit the full upstream ranges or omit the descriptor.
- **A date-only front matter value names a calendar day, not an instant**: `DateTime.parse('2026-01-01')` reads local midnight, so the same content emitted feed timestamps spanning 26 hours across four build machines. Feeds want the UTC-anchored instant; `sitemap.xml` `<lastmod>` wants the written calendar day and must **not** be zone-converted — routing it through `.toUtc()` moves it back a day for any zone east of UTC (TD-014, 0.11.0).
- **Visibility params and content data have different merge semantics**: theme params deep-merge (so `show_*` defaults survive a partial site config) while global data files replace **whole-file by stem**. A Lattice site overriding one key of `data/lattice.yaml` therefore kept every section switched on and lost the content for the rest — three empty `<h2>`s that live `aria-labelledby` attributes pointed at, `Built 5 pages`, exit 0, no warning. Gate a section on its data as well as its toggle.

- **Rebuilding onto the same origin/port serves you the cached script**: after rebuilding a theme's JS and reloading, Chrome replayed the *previous* file, producing a self-contradictory reading (`shell.hidden === true` while `input.disabled === false`) that still looks like a measurement rather than an error. Verification that rebuilds in place must change the origin — build onto a different port — or hard-bypass the cache. The same shape as serving from the wrong directory: the number arrives, it is just describing something else.
- **Verify a rendered claim against a render, not against the edit that should have caused it**: a contrast fix changed late in a run was reported with the figure implied by the CSS edit and never repainted. It happened to hold (4.57:1 → 6.83:1 when finally measured), but "I changed the token, therefore the ratio is X" is the same inference that let this cycle's rendering defects through a green suite.
- **The SSG minifies shipped CSS; contract tests assert the expanded form**: grepping a built stylesheet for `max-height: 320px` finds nothing because the served bytes say `max-height:320px`. `TrellisCss.compileSass` output (what the tests see) keeps the spaces. Grep the whitespace-stripped form when probing built output, or you manufacture a false negative and "fix" a rule that already shipped.
- **Concurrent agents collide on ports and on the browser**: three separate times in one cycle a measurement came from another agent's server on the intended port. Always `curl` the port and confirm a build-specific string before trusting a reading. And `agent-browser close --all` is *session-global* — it ignores `AGENT_BROWSER_SESSION` and kills every other agent's browser mid-run. Assign port ranges up front when fanning out browser-driving work.

- **Horizontal-overflow regressions cluster just *above* a declared breakpoint, not at round viewport widths**: Meadow's footer overflowed 6px at 768px because `.footer-inner` is a flex row above its 760px breakpoint and a column below — the failure window is ~761-800, a property of the breakpoint, not of 768. Themes declare a lot of these (folio 10 breakpoints, meadow 11, lattice 8), so a fixed sweep list covers one band by luck and misses the rest. Derive the sweep per theme from its own stylesheet — each `max-width: Npx` contributes `N+8` — and union it with a fixed narrow set for the unbreakable-token cases, which genuinely are a narrow-viewport failure. Layout-driven overflow needs the derived widths on a representative page; content-driven overflow needs the narrow widths on every fixture.
- **A declaration lookup must be scoped to the property, not just the selector**: returning the first rule matching a selector goes red on a *correct* stylesheet — `.search-results` first matches a grouped rule (`.sidebar-tree, …, .search-results { margin; padding; list-style }`) that declares nothing being asserted. Merging every matching rule is equally wrong: for `.hero` it folds in the `@media (max-width: 760px)` override and asserts `min-height: 0`. Look up the first rule that matches the selector **and** declares the property.
- **Parse declarations rather than accumulating anchors**: the prefix traps in these entries — `overflow:` matching inside `text-overflow:`, `column` inside `column-reverse`, `uppercase` inside `uppercase full-width`, `.foo` inside `.foo-DISABLED` — are all the same bug, and anchoring each one as it is discovered is an endless patch list. Split the rule body on `;` into property→value pairs and assert against the parsed value. The trap class disappears structurally instead of one regex at a time.
- **Asserting that a selector exists does not assert that it does anything**: 0.11's search-results defect was "title and snippet render inline and concatenate". The fix was styled and held by a ratchet deriving the class set from the script that emits it — which caught renames and deletions, and let every one of the four *declarations* be removed with the suite green. Rendered, the page returned to the verbatim original defect string. A class-existence ratchet secures the naming contract; the behaviour needs its own assertions on the declarations that produce it (`display`, `overflow-y`, `text-decoration`, `overflow-wrap`). Ask of every rule: if this selector kept its name and lost its body, would anything fail?
- **Sass drops empty rules, so "declares nothing" reads as "rule absent" in the compiled output**: a mutation that empties a rule body cannot be detected by iterating the surviving rules in the compiled CSS — the rule is simply gone, and an `every`-style assertion over what remains passes vacuously. Key such assertions by selector context and require the rule to be *present with* its declaration, rather than checking the declarations of whatever rules happen to exist.
- **A deliberately loose assertion needs a floor, not an anchor**: some value assertions are prefixes *by construction* — `--folio-grid: color-mix(in srgb, var(--folio-green)` leaves the percentage open so the tone can be tuned without churning the test. That looseness then admits `0%`, which resolves to fully transparent and erases the texture the assertion exists to protect, with the suite green. Anchoring would forbid legitimate tuning; the fix is a floor (`[1-9]\d*%`), verified by proving the degenerate value red *and* a neighbouring legitimate value still green.
- **CSS keyword values extend, so a substring match on one is not a match on its meaning**: `text-transform: uppercase` prefix-matches `uppercase full-width`, which Chrome rejects outright — computed `text-transform` becomes `none` and an entire mono-caps masthead silently renders in sentence case. Same family as `column`/`column-reverse` and `wrap`/`wrap-reverse`. Anchor enum values on the `;` as well as multi-value properties.
- **The verification tooling is as likely to be wrong as the thing it checks**: four times in one cycle a check produced a confident wrong answer — a self-validation grep that searched for the *replacement* string (trivially present); one that queried the light compile about a dark-only mutation; one that iterated surviving rules for a mutation whose whole effect was removing a rule; and a grouped-rule detector that matched the **CSS comments** above each rule, because comments contain commas and it read everything up to `{` as a selector list. Each reported a specific, entirely fictional finding. The rule that covers all four: **the self-check must assert the state the mutation was meant to create, in the artifact the assertion actually reads** — presence for a substitution, absence for a removal, and in the same compile the assertion consumes.
- **A mutation must be checked for having produced the defect it claims**: a rename applied to `.hero-center {` but not to `.hero-center .hero-copy` leaves the class still selected, so the suite correctly passes — and that reads exactly like a weak assertion. A "surviving" mutation is a finding only once you have confirmed the mutated tree is genuinely broken. Verify the defect first (render it, or grep the compiled output), then run the suite.
- **One passing mutation does not prove a test discriminates**: three separate assertions in 0.11 were mutation-proven and still could not catch the defect they existed for. A `lessThanOrEqualTo` byte cap went red on an oversized font and green on a **zero-byte** one. A node-gated check went red when its logic broke and vanished entirely — reporting "All tests passed" — when node was absent. `expect(css, contains('.search-result-title'))` went red on deletion and green on a **rename**, because `.search-result-title-DISABLED` contains the substring. In each case the author picked the mutation that matched the fix they had just made. Ask instead: what is the full set of ways this can break, and which of them does the assertion actually separate? Derive expected values from the other side of the contract (the script that emits the class, the file's own `fvar` axes) rather than hardcoding them, and anchor substring matches (`(?=[\s,{:])`) so a longer token cannot satisfy them.

## Release & Publishing

- **Hotfixes still get reviewed**: fresh-context adversarial review of the fix diff BEFORE tag push, every release incl. hotfixes – the 0.9.1 SASS-quoting hotfix shipped unreviewed with 4 real issues.
- **`dart test`/`dart analyze` at the workspace root do NOT cover the packages**: in a Dart workspace the root `dart test` runs only the root `test/` dir (34 tests) — not the ~1500 package tests. A CI job written that way is green while testing almost nothing. Drive per-package work through melos (`melos exec --dir-exists=test -- dart test`). Note `dart analyze` at root *does* span the workspace, so the two commands differ — don't generalize from one to the other.
- **melos scripts that use `exec:` need melos on PATH**: `dart run melos` fails inside them with `/bin/sh: melos: command not found`, because the script shells out to a `melos` binary. CI must `dart pub global activate melos` and add `~/.pub-cache/bin` to PATH, even though melos is already a root dev_dependency.
- **`melos run <script>` prompts for package selection and dies on a non-TTY**: it exits with `StdinException: Error getting terminal echo mode` in CI. Pass `--no-select`.
- **`dart test --tags=<tag>` exits 79 where nothing carries the tag**: fanned out across packages (only `trellis_cli` has `e2e` tags), a tag-filtered run fails every other package. Either scope to the packages that have the tag, or run the full suite and let `--exclude-tags` do the narrowing on the fast tier.
- **The release procedure is `dev/guidelines/RELEASE-RUNBOOK.md`; `tool/release.sh` is the entry point.** `melos version` (and so `tool/version_lockstep.sh`) throws `RestrictedBranchException` and changes nothing off `main` (root `pubspec.yaml` `melos.command.version.branch`) — the order is *merge → bump*, never *bump → merge*. The tag workflows refuse to publish unless `ci.yml` is green for the tagged commit and the commit is on `main` (`release-gate.yml` → `tool/require_green_ci.sh`); when the release commit and tag are pushed together the gate waits for CI, so a red release-gate job usually means "re-run it once CI is green", not "move the tag".
- **`dart pub publish --dry-run` exits non-zero on a dirty checkout** ("1 checked-in file is modified in git" is a *warning*, and warnings fail the dry-run). An uncommitted version bump is exactly that, so `tool/release.sh` commits first and undoes the commit if a dry-run fails.
- **Goldens must not bake source-file mtimes.** Three `trellis_site` byte-for-byte goldens (`path_prefix`, `prev_next`, `navigation_builder`) carried `<lastmod>`/`<updated>` values derived from fixture files' mtimes: green on the machine that captured them, red on every fresh clone (and on CI runners). Pages without `date:` fall back to `File.lastModifiedSync()`; git does not preserve mtimes. Fixed by pinning the fixture mtimes in `setUpAll` (`test/fixture_mtimes.dart`). Local "all green" is not CI green until the branch has actually run on GitHub.
- **pub.dev has no unpublish and no CLI retract.** A version can be *retracted* within 7 days on the package's pub.dev Admin tab (web only); it stays resolvable for existing `pubspec.lock`s and is skipped by new resolutions. After that, only a new patch release. Verified against https://dart.dev/tools/pub/publishing (2026-08-18).
- **GitHub API tag resolution:** `repos/{repo}/commits/tags/<tag>` returns 422 for *annotated* tags; the bare `repos/{repo}/commits/<tag>` form peels both annotated and lightweight tags to the commit. `compare/main...<sha>` `status` ∈ {`identical`,`behind`} means the commit is on `main`.
- **`tool/*.sh` must run on bash 3.2** (macOS `/bin/bash`): no `declare -A`, no `${var,,}`; use parallel indexed arrays. GitHub runners have bash 5, so the mismatch only shows locally.
- **`dart format` gates must cover the examples too**: `examples/*` are workspace members, so `packages/*/lib packages/*/test` misses them — `examples/todo_app` had drifted unnoticed. `melos run format:check` spans every member.
- **Retiring a theme param/asset requires a multi-surface propagation sweep**: the 0.10.0 review found the syntax_highlighting retirement (ADR-010) landed in code+themes but left 8 stale spots (5 independent reviewers): the standard-params contract ("19 params" count claim), the CLI theme scaffolder templates + its test (`packages/trellis_cli/lib/src/templates/`), arbor's `theme.yaml` description, both theme-authoring doc copies (`docs/guides` + `site/content`), and `dev/architecture/`. Before closing a retirement, grep the retired symbol repo-wide – incl. `docs/`, `site/content/`, CLI templates, `themes/*/theme.yaml`, `dev/architecture/` – and check count claims ("N params") near the removal site.
