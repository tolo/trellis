| TD-011 | trellis_site | Theme SASS param values are not validated for structural CSS characters (`;`, `{`, `}`). `theme_sass_generator.dart` `_toSassValue` neutralizes SASS *interpolation* (`#{...}`, so it can't be evaluated — remediated in the 0.9.2 follow-up review), but a value carrying `;{}` still reaches the generated SCSS: a **string** value silently corrupts the output CSS (e.g. `content: a; } html { background: red;` closes the rule early and injects another), and a raw **color** value aborts the compile. Not a security boundary in the SSG model — params are build-time author config (theme.yaml / site `theme_params:`), not untrusted runtime input — so this is a robustness limitation (a typo produces broken output or a cryptic abort), not an exploit. Proper fix: a single value-validation/escaping policy across all param types (string/color/list/map) that either rejects structural chars with a clear `SiteConfigException` naming the param, or defines an explicit neutralization. Assessed as its own effort — do not bundle. Source: docs-site SASS remediation follow-up review 2026-07-07 (F-C residue). | Low | docs-site |
